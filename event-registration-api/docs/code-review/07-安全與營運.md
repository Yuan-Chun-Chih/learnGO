# 07. 安全與營運邊界

[← 回到架構總覽](00-架構總覽.md)

這是本機教學專案，不是可直接公開部署的 production service。本文件沿著憑證進入系統、API 對外暴露、資料庫可用性和日常管理幾個方向檢視安全邊界。

## 憑證與帳號

- 密碼使用 bcrypt hash，API response 的 `User` 不含 hash 欄位。
- session token 使用 `crypto/rand` 產生；資料庫保存 SHA-256 hash，不保存明文 token。token 24 小時過期，logout 設定 `revoked_at`。
- 登入 response 設定 `Cache-Control: no-store`，避免 token 被一般 HTTP cache 保存。
- admin 透過一次性 `cmd/admin` 工具建立；`UpsertAdmin` 對相同 email 會更新名稱、密碼 hash 並設為 admin。操作者需保護該命令的環境變數，也要理解重跑的影響。

## 網路與部署設定

Compose 將主機 port 綁在 loopback，但這只限制本機 Docker 開發環境。容器內 API 監聽 `:8080`；把服務移到公開環境時，需要 TLS termination、受控 ingress/firewall、正式秘密管理及明確的網路策略。

Compose 預設 `POSTGRES_PASSWORD=localpass` 是方便本機試跑的預設值，不能拿去公開部署。`.env.example` 是範例，不是秘密庫；真實 `.env` 被忽略，不應提交。

## 可用性、日誌與健康檢查

- `/healthz` 表示程序能回 HTTP；`/readyz` 會以一秒 timeout ping DB，DB 不可用時回 503。
- API 和 migration startup 都有資料庫 ping；API 有連線池限制與 HTTP timeout，並在 SIGTERM 時嘗試 graceful shutdown。
- request log 包含 request ID、method、path、status、duration；不記錄 query、request body 或 bearer token。未處理錯誤會記錄 error，再回通用 500。
- session 到期紀錄目前不會自動清除；索引能支援查找，但長期運行仍會累積資料。

## 尚未實作的 production 能力

目前沒有 request rate limit、email 驗證、密碼重設、登入失敗鎖定、管理員操作 audit log、session 清理排程、metrics/tracing、備份還原流程或跨來源政策。實際需要依部署環境和威脅模型排序，不應僅靠這份清單就宣稱系統安全。

## Review 時追問

- 是否有任何 log、error 或 metrics label 可能意外帶出 token、email 或 SQL 參數？
- admin bootstrap 是否只允許可信任的部署操作者執行？
- secrets 是否透過 secret manager 或部署平台注入，避免留在 shell history、Compose 檔或 image layer？
- readiness fail 時部署平台會停止轉送流量嗎？healthcheck 本身不等於自動修復。
- DB 備份、migration rollback 和版本回復是否有演練？目前 Compose 只提供本機持久 volume，沒有備份流程。
