# 01. 啟動流程、依賴組裝與 Docker

[← 回到架構總覽](00-架構總覽.md)

從執行入口開始 review，可以先回答三件事：設定從哪裡來、依賴在哪裡組裝、程序如何停止。

## API 程序入口

入口是 [`cmd/api/main.go`](../../cmd/api/main.go)。`main` 建立 JSON `slog` logger 並呼叫 `run`；`run` 讀取 `DATABASE_URL`、開啟 pgx `database/sql` driver、設定連線池、以有 timeout 的 context ping 資料庫，接著組裝 Store、Service 和 HTTP server。

```text
DATABASE_URL
   → sql.Open("pgx", dsn)
   → db.PingContext(startupCtx)
   → store.NewPostgres(db)
   → core.NewService(repo)
   → httpapi.NewServer(service, repo, logger)
   → ListenAndServe
```

`sql.Open` 建立的是可延遲連線的連線池物件，啟動時的 `PingContext` 才確認資料庫可連線。池上限 10 條連線、最多 5 條 idle connection，並設定連線存活時間與 idle 時間。`PORT` 預設為 `8080`，並檢查範圍是否在有效 TCP port 內。

HTTP server 設定 `ReadHeaderTimeout`、`ReadTimeout`、`WriteTimeout`、`IdleTimeout`，降低連線無限等待的可能。收到 OS interrupt 或 SIGTERM 後呼叫 `Shutdown`，最多給 10 秒完成請求，再關閉資料庫連線池。

## 另外兩個執行入口

- [`cmd/migrate/main.go`](../../cmd/migrate/main.go)：以 `DATABASE_URL` 連資料庫，載入 embed 的 SQL migration，呼叫 Goose 將 schema 升級至最新版本。Compose 將它當作一次性工作執行。
- [`cmd/admin/main.go`](../../cmd/admin/main.go)：讀取管理員 email、名稱與密碼，bcrypt 雜湊密碼，再透過 `UpsertAdmin` 建立或更新管理員。它不會隨 API 啟動自動執行。

三個程式共用相同 Go module 和 PostgreSQL adapter，但生命週期不同：API 是常駐服務，migration 與 admin 是一次性命令。review 時可以確認各入口是否都在使用資料庫前設定 timeout、檢查必需環境變數並關閉連線。

## Compose 啟動依賴

[`compose.yaml`](../../compose.yaml) 定義以下順序：

```text
db healthcheck 成功
  → migrate 執行並成功結束
  → api 啟動
```

`depends_on` 配合 `service_healthy` 和 `service_completed_successfully`，使 API 不會只因資料庫容器「已啟動」就開始服務。API 的 healthcheck 呼叫 `/readyz`；資料庫資料放在命名 volume `postgres_data`，因此一般 `docker compose down` 不會移除資料。

Compose 預設把 PostgreSQL 綁定到 `127.0.0.1:5433`，API 綁定到 `127.0.0.1:${API_PORT:-18080}`。這是本機開發設定。`db-test` 使用獨立的 test database 與 tmpfs，供 `test` profile 執行整合測試。

## Docker image

[`Dockerfile`](../../Dockerfile) 分成 build stage 和 runtime stage：build stage 使用 Go image 編譯 API、migration、admin 三個 binary；最終 image 使用 Alpine、複製 binary、建立非 root 使用者 `app`，再以該使用者執行服務。

## Review 時追問

- API 在 migration 失敗時是否會被 Compose 阻止啟動？目前由依賴條件保證。
- 開發資料和整合測試資料是否隔離？目前使用不同 service、database 名稱和儲存方式。
- `POSTGRES_PASSWORD` 的預設值、port 綁定與 image tag 適不適合 production？目前明確是本機教學設定。
- shutdown timeout 是否足以涵蓋最慢的請求？若服務工作時間變長，需要重新評估 server 和 shutdown timeout。
- admin upsert 被重複執行時的效果是否符合操作者預期？該命令會提升既有 email 帳號權限並重設密碼。
